# 엄마 레시피 웹앱 개발 프로세스

85세 어르신이 주방에서 스마트폰이나 태블릿으로 편하게 볼 수 있도록 만든 모바일 전용 레시피 웹앱입니다. 이 문서는 다음에 비슷한 웹앱을 다시 만들 때 처음부터 끝까지 따라 할 수 있도록 정리한 개발 기록입니다.

## 1. 목표 정하기

먼저 앱의 사용자를 분명히 정했습니다.

- 사용자: 85세 어르신
- 사용 장소: 주방
- 사용 기기: 스마트폰 또는 태블릿
- 핵심 목적: 레시피를 크게 보고, 재료를 체크하고, 직접 만든 음식 사진을 보관하기

이 목표 때문에 일반적인 예쁜 웹사이트보다 다음 조건을 우선했습니다.

- 글자는 매우 크게
- 버튼은 손가락으로 누르기 쉽게 크게
- 색상은 고대비로 선명하게
- 화면 구조는 단순하게
- 빌드 없이 `index.html` 하나로 실행 가능하게

## 2. 기술 선택

복잡한 프레임워크를 쓰지 않고 단일 HTML 파일로 만들었습니다.

- HTML: 화면 구조
- CSS: 큰 글자, 큰 버튼, 모바일 레이아웃
- Tailwind CDN: 간단한 유틸리티 스타일 보조
- Vanilla JavaScript: 화면 전환, 레시피 추가, 자동 채우기, 사진 저장
- localStorage: 사용자가 추가한 레시피 저장
- IndexedDB: 음식 사진 저장
- GitHub Pages: 무료 정적 웹 배포

이 방식의 장점은 서버가 없어도 작동하고, 수정할 파일이 `index.html` 하나라 관리가 쉽다는 점입니다.

## 3. 화면 설계

현재 앱은 세 가지 주요 화면으로 구성되어 있습니다.

1. 분류 화면
   - `종류별` 버튼만 표시
   - 밑반찬, 메인반찬, 국/탕, 찌게, 김치/젓갈/장 등 분류 선택

2. 레시피 목록 화면
   - 선택한 분류의 레시피 목록 표시
   - 목록 맨 위에 `+ 새 메뉴 추가` 버튼 표시
   - 각 레시피는 큰 제목, 설명, 인분, 시간 정보를 보여줌

3. 레시피 상세 화면
   - 큰 요리 제목
   - 준비물 체크 기능
   - 만드는 법 단계 카드
   - 음식 사진 추가/삭제 기능
   - 처음 화면으로 돌아가기 버튼

## 4. 데이터 구성

기본 레시피는 JavaScript 배열로 관리합니다.

```js
{
  name: "소고기 장조림",
  categories: ["전체", "밑반찬"],
  desc: "짭조름하고 부드러운 밥도둑 장조림입니다.",
  servings: "4인분",
  time: "60분",
  ingredients: ["소고기", "메추리알", "간장"],
  steps: ["고기 핏물을 빼세요.", "간장 양념에 조리세요."]
}
```

분류별로 메뉴 수를 늘리기 위해 `menuNamesByCategory`에 음식 이름 목록을 두고, 부족한 상세 정보는 자동 샘플 레시피로 생성합니다.

## 5. 새 메뉴 추가 방식

사용자가 직접 메뉴를 추가할 수 있도록 `새 메뉴 추가` 화면을 만들었습니다.

입력 항목:

- 음식 이름
- 분류
- 준비물
- 만드는 법

저장 위치:

- 추가한 레시피는 브라우저 `localStorage`에 저장됩니다.

주의할 점:

- 같은 기기, 같은 브라우저에서만 유지됩니다.
- 브라우저 데이터를 삭제하면 추가한 레시피가 사라질 수 있습니다.

## 6. 자동으로 채우기 기능

인터넷이나 유튜브에서 직접 정보를 가져오는 방식은 API 키와 서버가 필요해서 단일 HTML 앱에는 적합하지 않습니다.

대신 앱 안에서 음식 이름과 분류를 보고 준비물과 만드는 법 초안을 자동 생성하게 만들었습니다.

예:

- 음식 이름: `김치찌게`
- 분류: `찌게`
- 자동 생성: 김치, 두부, 대파, 마늘, 고춧가루 등을 준비물로 채움

사용자는 자동으로 채운 내용을 보고 수정한 뒤 저장할 수 있습니다.

## 7. 음식 사진 보관 기능

레시피 상세 화면에서 `사진 추가하기` 버튼을 누르면 카메라 촬영 또는 앨범 선택이 가능합니다.

사진 처리 방식:

- 선택한 사진을 브라우저에서 압축
- 레시피별로 IndexedDB에 저장
- 상세 화면에서 사진 목록 표시
- 개별 사진 삭제 가능

사진은 용량이 크기 때문에 `localStorage`가 아니라 `IndexedDB`를 사용했습니다.

## 8. 로컬 실행 방법

프로젝트 폴더에서 로컬 서버를 실행합니다.

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

브라우저에서 아래 주소를 엽니다.

```text
http://127.0.0.1:8000
```

단순 확인만 할 때는 `index.html` 파일을 직접 열어도 되지만, 카메라/저장 기능은 브라우저 정책 때문에 로컬 서버로 확인하는 편이 좋습니다.

## 9. 검증 방법

수정 후 최소한 다음을 확인합니다.

1. 로컬 페이지가 열리는지 확인
2. 분류 버튼이 작동하는지 확인
3. 레시피 상세 화면으로 이동되는지 확인
4. 준비물 체크가 되는지 확인
5. 새 메뉴 추가가 저장되는지 확인
6. 자동으로 채우기가 동작하는지 확인
7. 사진 추가와 삭제가 동작하는지 확인

JavaScript 문법 검사는 아래 방식으로 할 수 있습니다.

```powershell
node -e "const fs=require('fs'); const html=fs.readFileSync('index.html','utf8'); const m=html.match(/<script>([\s\S]*)<\/script>/); new Function(m[1]); console.log('JS syntax OK');"
```

## 10. GitHub 배포 방법

이 앱은 정적 웹앱이라 별도 빌드가 필요 없습니다.

기본 흐름:

```powershell
git add index.html README.md
git commit -m "Update recipe app"
git push origin main
```

GitHub Pages는 `gh-pages` 브랜치 루트의 `index.html`을 배포합니다.

```powershell
git switch gh-pages
git checkout main -- index.html README.md
git add index.html README.md
git commit -m "Deploy recipe app"
git push origin gh-pages
```

배포 주소:

```text
https://jgjeong730.github.io/mamicook/
```

GitHub Pages는 반영에 시간이 조금 걸릴 수 있습니다. 배포 직후 이전 화면이 보이면 30초에서 2분 정도 기다린 뒤 새로고침합니다.

## 11. 다음에 비슷한 앱을 만들 때 순서

1. 사용자를 정한다.
2. 사용 장소와 기기를 정한다.
3. 가장 중요한 기능 3개만 먼저 정한다.
4. 첫 화면 구조를 종이에 그린다.
5. `index.html` 하나로 시작한다.
6. HTML로 화면 뼈대를 만든다.
7. CSS로 글자, 버튼, 색상, 간격을 잡는다.
8. JavaScript로 화면 전환을 만든다.
9. 샘플 데이터를 넣는다.
10. 저장이 필요하면 `localStorage` 또는 `IndexedDB`를 쓴다.
11. 로컬 서버에서 확인한다.
12. GitHub에 커밋한다.
13. `gh-pages`로 배포한다.
14. 실제 휴대폰에서 확인한다.

## 12. 확장 아이디어

앞으로 추가할 수 있는 기능입니다.

- 추가한 레시피 수정 기능
- 추가한 레시피 삭제 기능
- 사진 여러 장에 메모 남기기
- 레시피 검색 기능
- 글자 크기 더 크게/작게 설정
- 가족끼리 데이터를 공유하는 서버 연동
- 백업/복원 기능

현재 구조에서 가장 먼저 추가하면 좋은 기능은 `레시피 수정/삭제`와 `백업/복원`입니다.
